# PitFireTeam 1.1.1 against the adapter (2026-11-07)

PitFireTeam (PFT) 1.1.1 (GitHub release of 2026-11-05, tag `7105ec54`; the installed
server DLL is stamped `1.1.1+b0503e8e`, the installed client carries the tag's
team-split code) replaced the reviewed 1.0.0 on the development machine and the test
hosts on 2026-11-05. This review answers whether ArenaMode's adapter needs changes,
records the changes made, and makes 1.1.1 a reviewed baseline. ArenaMode admits
0.10.0 and every build from 0.10.3 on; a build that is not a reviewed baseline is
admitted with one advisory Warning on the client and the server.

## Method

- Every PFT type, member, route and reason string ArenaMode reflects on was listed
  from `ArenaMode.Client/Compat/PitFireTeam*.cs`, `ArenaMode.Shared/PitFireTeamVersions.cs`
  and the server-side protection (`ArenaMode.Server/Patches/PitFireTeam*.cs`), and
  compared between PFT 1.0.0 (`f32a41b2`) and the installed 1.1.1: the GitHub source at
  `b0503e8e` and `7105ec54`, and a decompile of the installed client and server DLLs
  (authoritative where source and binary differ).
- PFT's raid hooks that changed (`RaidStartPatch`, `BotsControllerPatch`, `PlayerPatch`,
  the new patches of 1.1.1) were read against Arena's round lifecycle (the frozen roster,
  the leased follower respawn of rounds 2 and later, the protected stop).
- Offline harnesses against the installed 1.1.1: `PitFireTeamChecks` (381 assertions,
  installed-metadata checks included), `PftPortedMapChecks` (314), `PftTacticalKitChecks`
  (165 plus 956 menu assertions) passed. `PitFireTeam100Checks` needs the exact 1.0.0
  release folder (`artifacts/pft-100-contracts/release`) and `PitFireTeamRoundLifecycleChecks`
  needs the beta-0.10.0 reference checkout; neither folder is present on this machine, so
  neither ran (they pin older baselines, not the installed plugin).
- Seven review agents and sixteen adversarial checks (two independent skeptics per
  finding rated above advisory); only findings that survived are listed as changes.

## Changes made for 1.1.1 (all gated on an installed PFT assembly of 1.1.0 or newer)

1. **Served saved-spawn-settings preflight for the leased follower respawn.** 1.1.1's
   `BotsControllerPatch.SpawnGroupBots` awaits a new `LoadSavedSpawnSettings` (a thread-pool
   `GET /client/game/bot/followerdetails`, up to three attempts) before
   `BotCreationData.Create`; in 1.0.0 that request was synchronous. Arena's spawn lease marks
   only the synchronous window of its own `SpawnGroupBots` call and captures the count-zero
   `Create` inside it, so with 1.1.1 every leased respawn (rounds 2 and later in Tactical and
   Zombies) returned an incomplete task before `Create` and failed the round with
   "PFT SpawnGroupBots returned without the exact count-zero BotCreationData.Create lease".
   Arena now remembers the completed `LoadSavedSpawnSettings` task of the natural round-1
   spawn for the frozen roster and hands it back inside its leased call, so the state machine
   continues synchronously to `Create` as the lease requires. Without a remembered result
   PFT's own preflight runs and the lease reports why it failed.
2. **Kill-report guard covers the new overload.** `FriendlyEncounterPenaltyRuntime.SendKillReport`
   gained a six-argument overload (`bool affectsRecruitment`) that `PlayerKilledPatch` calls
   directly; the five-argument one Arena patched only forwards. The guard now requires and
   patches both, so a qualifying kill in an Arena raid no longer posts
   `/singleplayer/pitfireteam/postraid/kill-message` or registers a local penalty.
3. **Stop-cleanup contract mirrors the two new resets.** PFT's stop prefix additionally calls
   `CompanionRaidPreparation.Reset()` and `FollowerRaidHealthRetention.Clear()`; Arena's
   fallback contract (replayed only when PFT's own prefix throws during a protected stop) now
   contains both. Low impact, kept for the contract's completeness.
4. **1.1.1 is a reviewed baseline** (`PitFireTeamVersions`: 0.10.0, 0.10.3, 1.0.0, 1.1.1); the
   whitelist records client and server 1.1.1. 1.1.0 and later 1.1.x builds stay admitted with
   the advisory.

Builds below 1.1.0 keep today's bindings byte for byte.

## Checked and left alone

- **Saved teammates and health.** 1.1.1 no longer restores a saved teammate to full health on
  activation when the server registered its profile (`FollowerRaidHealthRetention`). The PFT
  server refuses to spawn a wounded teammate at all, and Arena's round 2+ clones carry fresh
  profile ids and are healed by PFT's fallback, so companions still start every round at
  full health. No change. The flip side is a new limit: a companion wounded in a normal raid
  is refused by PFT 1.1.1 at the Arena raid start, Arena's protected modes need their exact
  companion count and abort the start with the follower-preparation diagnostic; Arena's
  selection has no health awareness, so the player heals the companion in PFT's menu first.
  Documented in the release notes; a health-aware selection is possible later.
- **New server transactions** (teammate treatment and its quote, voice, the companion raid
  preparation, the Blazor teammate editor) are not in ArenaMode's management contract
  tables. Their persistence goes through `TeammateDatabase`, whose writes are blocked for a
  protected session, and they are menu operations that run outside the armed window; the
  rows can be added later as hardening.
- **Fail-closed follower spawn.** 1.1.1 awaits every follower activation (registration within
  8 s of the raid start, readiness polls) and aborts the whole group when the saved metadata
  of a selected account is missing or its role differs, with a log error and an in-raid toast
  where 1.0.0 fell back to defaults; Arena's start-of-match wait tolerates the extra round
  trip. Observed in the native run below.
- **Team split, Going Rogue, SAIN tracking reports, found-in-raid and UI patches** are additive
  and do not touch the members Arena binds; Going Rogue (a separate addon) is not installed
  and not reviewed.

## Native check

GPU-2, 2026-11-07, the 0.5.0 package binaries with PitFireTeam 1.1.1: a Tactical match on Factory
with two companions over three rounds. The natural round-1 preflight was remembered during the
deploy countdown (before `ArenaSession.IsActive` latched, which is why the postfix uses the arming
predicate), and the leased respawns of rounds 2 and 3 logged `Arena served PFT's saved-spawn-settings
preflight from the round-1 result for 2 follower account(s)`, followed by the fresh follower bodies
passing the registry barrier and being adopted; the match ended 0-3 with the profile snapshot
restored and no kill-message request on the server. Record:
[GPU-RELEASE-050-20261107.md](../reports/2026-11/GPU-RELEASE-050-20261107.md).

## Traps

- The installed client DLL is the tag build while the server DLL is stamped `b0503e8e`; the
  decompiled binaries, not the source tags, are what the adapter was reviewed against.
- `PitFireTeam100Checks` and `PitFireTeamRoundLifecycleChecks` pin the 1.0.0 release and the
  0.10.0 reference checkout; they do not read the installed plugin and need those folders.
