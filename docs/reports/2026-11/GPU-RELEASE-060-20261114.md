## Acceptance bookkeeping

- **Profile.** A first comparison (the copy of 12:08, before the packages were installed,
  against 12:30, after the four Arena raids of sections 1 to 4) showed more than the two
  bookkeeping timestamps: SPT's own entries for the two new mod versions under `spt/mods`,
  energy and hydration back at 100 (from 90 and 96), and an explicit `upd.StackObjectsCount: 1`
  on two equipment items (the dogtag and the scabbard). The server log names the cause of the
  last one: SPT's `ProfileFixerService` logged `Fixed item: …s undefined StackObjectsCount value,
  now set to 1` for exactly these two items at 11:18:36 UTC, when the profile was loaded at the
  game start after the server restart and before the first raid. As [TRAPS.md](../../TRAPS.md)
  demands, that comparison is not counted and was repeated: with a fresh copy taken at 12:31,
  the profile after the Customs Yard raid differs in `Hideout/sptUpdateLastRunTimestamp` and
  nothing else. The other profiles were byte-identical in both comparisons. The normal Factory
  raid of section 7 changes the profile as a normal raid does and is not part of the comparison.
- **PitFireTeam.** All 61 files of the PitFireTeam server mod were byte-identical between 12:08
  and the end of the Arena raids, the squad raid included.
- **Config.** gpu-run's menu choices changed `Team Deathmatch › ExperimentalArea` (to
  `customs-yard-polygon-v1`) and `AreaPlayersPerTeam` (5 to 3); both were put back with the game
  closed. `com.maschine.ArenaMode.cfg` then equals the copy from before in every line but the
  first, where BepInEx names the plugin version that wrote the file (v0.6.0, was v0.5.0), and
  the development machine and GPU-2 hold the same file. `com.maschine.Redeploy.cfg` differs in
  that header line only (v1.1.3). The Tactical test timings never reached the file.
- **End state.** The game is closed and the GPU-2 server stopped.
